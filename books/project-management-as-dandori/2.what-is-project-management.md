# プロジェクトマネジメントの概要

- **ひとことで**: 目的を定め、計画を遂行して達成する
  - そのためのプロジェクトマネジメントが必要
- 主な要素:
  - 目的
  - 課題分析
  - 戦略・計画
  - リスク
  - 遂行・調整

# 簡単な歴史

- アメリカのオペレーションズリサーチ（OR）等のルーツ
- 分野の確立
- 体系化
- 重厚長大さへの反省

# 段取りとは

- 一般的な定義
- 本書での定義: **「もったいない」を無くす**とおいてみる
- 業務は最良の計画よりは早まらない（短縮自体は各ステークホルダーの能力や貢献に依存する）
- 「もったいない」を削るだけでも十分に早くなる（通常は無駄が多すぎる）

# プロジェクトマネジメントの難しさ

- **初めての内容・一点物**: 開発のプロセス自体は繰り返しであっても、開発で作る対象は毎度新しいことが多い
- **成功の再現性は低い**
- **敵である不確実性（実際には不可視領域）を扱っていく**

# 集中的に行うプロジェクトマネージャーという役割・専任者

- 組織間・役割間・専門間の境界をまたいで情報と意思決定を流す役割を持つ
- 特定個人に集中させるのではなく、各個人が自ら行うことで専任者を不要にしていきたい
- そのためには、フィードバックループの小規模化・高頻度化・分散化が重要
